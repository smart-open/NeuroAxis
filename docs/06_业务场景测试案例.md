# 业务场景测试案例（链路级）

> 本文记录 P0 阶段已实现的**业务场景全链路测试**：每个场景从 Spec（YAML）出发，依次通过 Schema 校验 → 语义校验（V 规则）→ IR 构建 → 等价 ST 程序 → 虚拟时钟仿真 → 输出时间线断言。全部确定性可重放（同输入 → 同 trace SHA256）。
>
> 代码位置：`tests/test_scenarios.py`（用例）、`tests/test_e2e_generated.py`（W3 生成链路用例）、`src/plcagent/scenarios/runner.py`（链路 Runner）。

## 1. 链路定义

```
Spec (YAML 文本)
  ↓ plcagent.spec.loader.load_spec
Schema 校验（JSON Schema，结构层）
  ↓
语义校验（V1/V4/V5/V6/V11/V12/V13/V15/V16，语义层）
  ↓
IrProject（冻结 Pydantic，Guard 为语法树）
  ↓ （W3 起：plcagent.gen.render(ir) 生成 ST，S 规则静态检查后进入仿真）
ST 程序 → st.parser → 解释器（VirtualClock 驱动，扫描循环）
  ↓ io_write 插桩
TraceRecorder（事件时间线 + SHA256 摘要）
  ↓
断言（expect 点值 / assert_never 不变式）→ ScenarioResult
```

**断言语义**：
- `Expect(signal, value, scan)`：扫描 `scan` 时该信号的**最后已知值**必须等于 `value`（输出在两次赋值之间保持，即 IEC 扫描语义；从未写过的 BOOL 读为 FALSE 默认值）。
- `AssertNever(signal, value)`：整个用例期间该信号不得出现该值（安全不变式）。

## 2b. W3 端到端升级链路（E2E-SC，Spec → 生成器 → 仿真）

> W3 落地 `plcagent.gen` 后，同一批场景改用**生成器产出的 ST** 跑链路，不再使用手写等价程序。链路：`load_spec → check_ir（R 规则门）→ gen.render → check_st（S 规则门）→ run_chain`。

| 场景 | 工艺 | 关键断言 | 用例数 | 结果 |
|---|---|---|---|---|
| E2E-SC01 | 单电机启停保持（生成 ST） | 启动脉冲下扫描吸合 / 自锁 / 停止 / 急停断开 | 1 | ✅ PASS |
| E2E-SC02 | 正反转互锁（生成 ST） | 正转吸合 / 换向无误动 / 停止释放 | 1 | ✅ PASS |
| E2E-SC02X | 同按双键（生成 ST） | Fwd/Rev 同按拒动（互斥守卫） | 1 | ✅ PASS |
| E2E-SC04 | 手自动+急停复位（生成 ST） | 自动启动 / 急停断带+故障灯 / 复位清故障 / 手动点动 | 1 | ✅ PASS |
| E2E-SC04R | 复位闸门（生成 ST） | 复位前 Start 无效 / 复位后自动恢复 | 1 | ✅ PASS |
| 生成确定性 | 同 Spec 三次 render 字节一致 | 摘要唯一 | 1 | ✅ PASS |

合计 **6 个端到端生成链路测试全绿**。链路在 `_generated()` 处内嵌两道门：IR 上 R 规则（安全不可关闭）与生成 ST 上 S 规则——任一不通过则场景直接失败。

**链路拦截记录（W3）**：
1. `Conv_Run:=Manual_Jog`（标识符引用动作）曾使 `IrAction` 校验失败（value 不含 str）——暴露 IR 模型缺口，已扩展 `value: bool | int | float | str`，生成器将标识符渲染为变量读取。
2. 生成 ST 首扫描即被通配 prio-0 急停边送入 Fault（`EStop_OK` 默认 FALSE）——验证了安全边在**上电首扫描即生效**的正确行为。

## 3. 各场景详细记录

### SC-01 单电机启停保持

**Spec 要点**：`Motor` 状态机（Idle/Run），`Start_PB AND EStop_OK` 启动，`Stop_PB OR NOT EStop_OK` 停止，急停互锁强制 `Motor_Run:=0`。

**输入脚本**（scanMs=10，120 扫描）：Start 脉冲 scan 2；Stop 脉冲 scan 50；急停断开 scan 80。

**断言与结果**：

| 断言 | 期望 | 结果 |
|---|---|---|
| Motor_Run=TRUE @ scan 3 | 启动脉冲后下一扫描吸合 | ✅ |
| Motor_Run=TRUE @ scan 49 | 自锁保持 47 扫描 | ✅ |
| Motor_Run=FALSE @ scan 51 | 停止按钮释放 | ✅ |
| Motor_Run=FALSE @ scan 81 | 急停强制断开 | ✅ |
| 5 次运行 digest 全等 | 确定性 | ✅ `95e6957a…` |

### SC-02 电机正反转互锁

**Spec 要点**：`Direction` 状态机（Stopped/Forward/Reverse），`prio 0` 的 `"*"` 边统一处理停止/急停，急停互锁双断。

**发现并修复的设计问题**：
1. 两台转移同用 `prio: 1` → 语义校验 **V6 命中**（同 from 优先级重复）——正是校验器该拦的错误，Rev 改 prio 2 后通过。
2. 同按 Fwd+Rev 双键：初版 ST 会吸合正转——补 `NOT Rev_PB` / `NOT Fwd_PB` 互斥条件后，**同按双键两路都不动**（验证互锁真实生效）。

**输入脚本**：Fwd @2、Rev @40、Stop @60；EStop 恒正常。

| 断言 | 期望 | 结果 |
|---|---|---|
| Fwd_Out=TRUE @3 | 正转吸合 | ✅ |
| Rev_Out=FALSE @41 | 换向瞬间反转未误动 | ✅ |
| Fwd_Out=FALSE @61 | 停止释放 | ✅ |
| 同按双键 @9 双输出均 FALSE | 互斥拒动 | ✅ |

### SC-03 单气缸往复 + 超时报警（故障注入）

**Spec 要点**：`Cylinder` 状态机（Retracted/Extending/Fault），`ExtTimeOut=1s` 参数，急停互锁断阀。

**用例 1 正常循环**：启动 @2 → 伸出到位 50~80（500ms 行程）→ 到位断阀 → `assert_never(Alarm_Fault=TRUE)` 全程不报警。✅

**用例 2 超时故障**（`Cyl_Extended: stuck_0` 注入，传感器恒 0）：

| 断言 | 期望 | 结果 |
|---|---|---|
| Cyl_Out=TRUE @3 | 阀得电伸出 | ✅ |
| Cyl_Out=TRUE @100 | 980ms 时仍在计时未超时 | ✅ |
| Alarm_Fault=TRUE @104 | 计满 100 扫描（1s）转 Fault 报警 | ✅ |
| Cyl_Out=FALSE @104 | 超时断阀 | ✅ |

> 注：ST 子集的 FB 调用语法（`TON(IN:=…, PT:=…)` 与 `Timeout.Q` 成员访问）属 W4 序列模板范围，本场景以 DINT 扫描计数器表达同一超时语义（scanMs=10 × 100 扫描 = 1s），语义等价且确定性相同。

### SC-04 手自动模式 + 急停全局复位

**Spec 要点**：`LineCtl` 状态机（Idle/Run/Fault），`prio 0` 急停 `"*"` 边进 Fault，Fault→Idle 需 `Reset_PB AND EStop_OK`，手动点动走 `manualOnly` 互锁行。

**用例 1 全状态巡游**：Auto 启动 @10 → 运行 → 急停 @40 → Fault → 复位 @70 → Manual 点动 @90~110。

| 断言 | 期望 | 结果 |
|---|---|---|
| Conv_Run=TRUE @11 | 自动模式启动 | ✅ |
| HMI_Fault=TRUE @41 | 急停亮故障灯 | ✅ |
| Conv_Run=FALSE @41 | 急停断带 | ✅ |
| HMI_Fault=FALSE @71 | 复位清除故障 | ✅ |
| Conv_Run=TRUE @91 | 手动点动经互锁吸合 | ✅ |
| Conv_Run=FALSE @111 | 松开点动释放 | ✅ |

**用例 2 复位闸门**：运行中急停 → 故障期间按住 Start 无效 → 复位后（Start 仍按住）自动恢复。

| 断言 | 期望 | 结果 |
|---|---|---|
| Conv_Run=FALSE @30 | 急停期间保持断开 | ✅ |
| Conv_Run=FALSE @85 | **未复位时 Start 不得重启**（安全闸门） | ✅ |
| HMI_Fault=FALSE @91 | 复位后故障清除 | ✅ |
| Conv_Run=TRUE @92 | 复位后自动恢复 | ✅ |

## 5. 与计划的对应关系

- 本链路 = 14.2「端到端层」：W3 生成器已落地（`plcagent.gen`），等价手写 ST 已由 `IR→ST` 生成产物替换（见 2b 节 E2E-SC 链路），即 **Spec → 生成 ST → 仿真** 的真正端到端。
- SC-01/02 对应评测集 14.3 A 组前两题；SC-03 对应 B 组"带超时报警的夹紧"简化版；SC-04 对应 D 组"手自动切换/故障复位"组合。
- 黄金基线（`expected/` trace 重录流程）在 W4 Runner 完整落地时接入本链路。
