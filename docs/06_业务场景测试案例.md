# 业务场景测试案例（链路级）

> 本文记录 P0 阶段已实现的**业务场景全链路测试**：每个场景从 Spec（YAML）出发，依次通过 Schema 校验 → 语义校验（V 规则）→ IR 构建 → 等价 ST 程序 → 虚拟时钟仿真 → 输出时间线断言。全部确定性可重放（同输入 → 同 trace SHA256）。
>
> 代码位置：`tests/test_scenarios.py`（用例）、`tests/test_e2e_generated.py`（W3 生成链路用例）、`tests/test_plant_dsl.py` + `tests/test_d1_project.py`（W4 仿真台链路）、`src/plcagent/scenarios/runner.py`（链路 Runner）、`src/plcagent/dsl.py`（5.4 DSL Runner）。

## 1. 链路定义

```
Spec (YAML 文本)
  ↓ plcagent.spec.loader.load_spec
Schema 校验（JSON Schema，结构层）
  ↓
语义校验（V1/V4/V5/V6/V11/V12/V13/V15/V16，语义层）
  ↓
IrProject（冻结 Pydantic，Guard 为语法树）
  ↓ （W3 起：plcagent.gen.render(ir) 生成 ST，S 规则静态检查后进入仿真）
ST 程序 → st.parser → 解释器（VirtualClock 驱动，扫描循环）
  ↓ io_write 插桩
TraceRecorder（事件时间线 + SHA256 摘要）
  ↓
断言（expect 点值 / assert_never 不变式）→ ScenarioResult
```

**断言语义**：
- `Expect(signal, value, scan)`：扫描 `scan` 时该信号的**最后已知值**必须等于 `value`（输出在两次赋值之间保持，即 IEC 扫描语义；从未写过的 BOOL 读为 FALSE 默认值）。
- `AssertNever(signal, value)`：整个用例期间该信号不得出现该值（安全不变式）。

| 场景 | 工艺 | 关键断言 | 用例数 | 结果 |
|---|---|---|---|---|
| E2E-SC01 | 单电机启停保持（生成 ST） | 启动脉冲下扫描吸合 / 自锁 / 停止 / 急停断开 | 1 | ✅ PASS |
| E2E-SC02 | 正反转互锁（生成 ST） | 正转吸合 / 换向无误动 / 停止释放 | 1 | ✅ PASS |
| E2E-SC02X | 同按双键（生成 ST） | Fwd/Rev 同按拒动（互斥守卫） | 1 | ✅ PASS |
| E2E-SC04 | 手自动+急停复位（生成 ST） | 自动启动 / 急停断带+故障灯 / 复位清故障 / 手动点动 | 1 | ✅ PASS |
| E2E-SC04R | 复位闸门（生成 ST） | 复位前 Start 无效 / 复位后自动恢复 | 1 | ✅ PASS |

合计 **6 个端到端生成链路测试全绿**。链路在 `_generated()` 处内嵌两道门：IR 上 R 规则（安全不可关闭）与生成 ST 上 S 规则——任一不通过则场景直接失败。

**链路拦截记录（W3）**：
1. `Conv_Run:=Manual_Jog`（标识符引用动作）曾使 `IrAction` 校验失败（value 不含 str）——暴露 IR 模型缺口，已扩展 `value: bool | int | float | str`，生成器将标识符渲染为变量读取。
2. 生成 ST 首扫描即被通配 prio-0 急停边送入 Fault（`EStop_OK` 默认 FALSE）——验证了安全边在**上电首扫描即生效**的正确行为。

## 2c. W4 仿真台链路（PLANT-SC，Spec → 生成 ST → 虚拟设备 → DSL 套件）

> W4 落地虚拟设备库（`plcagent.plant`，12 种核心设备四族）与测试 DSL Runner（`plcagent.dsl`，5.4 全部 7 关键字）。D1 样例工程（`examples/d1_project.py`）成为真正的 **Spec → 生成 ST → 虚拟物理设备 → YAML 用例** 全链路。

| 场景 | 工艺 | 关键验证点 | 用例数 | 结果 |
|---|---|---|---|---|
| 设备库 | 12 种组件物理模型 | 气缸整型毫秒计数消除浮点累加误差 / 输送线队列+光电 / 液位积分+限位 / 一阶响应 / 故障注入 stuck_0 | 11 | ✅ PASS |
| DSL Runner | 7 关键字语义 | set/init 仅允许输入点 / expect 虚拟时钟窗口（超窗报错）/ assert_never 违例捕获 / drive 组件方法 / 确定性摘要 | 6 | ✅ PASS |
| D1-estop | 分拣机安全回路断开 | Conv_Run 立断 + HMI_Fault 亮 + 全程不变式 `Conv_Run AND NOT Safety_OK` | 1 | ✅ PASS |
| D1-push | 正常分拣循环 | 启动 → drive push_item → 光电（物理时间 ~4900ms）→ 推杆 → 不变式 `Push_Out AND NOT Conv_Run` | 1 | ✅ PASS |
| D1 门禁 | R 规则 + S 规则内嵌链路 | Spec 过 R 规则、生成 ST 过 S 规则后才允许进仿真 | 2 | ✅ PASS |
| D1 确定性 | 套件跑 3 次摘要全等 | 链路级确定性 | 1 | ✅ PASS |

合计 **22 个 W4 测试全绿**（仓库全套 113 passed）。新增能力：

- **组件注册机制**：`@ComponentRegistry.register("kind")`，新设备 = 一个类 + 一行注册 + 单测，不动解释器与 Runner（5.3 硬要求）。
- **信号命名**：组件端口 = `{组件名}_{端口}`（如 `belt_pe_out`）；`set/init` 直接写 PLC VAR_INPUT 名（direct bridge，桥接不得覆盖）。
- **双向桥接**：plant→PLC（传感器）与 PLC→plant（执行器输出）两个方向，`apply_bridge` 统一处理。

**链路拦截记录（W4）**：
1. 气缸行程用浮点累加 `0.0005×2000` 永远到不了 1.0（二进制不精确）——改整型毫秒计数，物理时间精度由 scanMs 保证。
2. expect 时间窗起点错误：初版以**用例起点**计时（`now_ms >= 200ms` 恒真，扫一个扫描就超窗）——改为以**上一步骤完成时刻**为锚（5.4 语义），`step["start_scan"]` 记录锚点。
3. 桥接覆盖用户输入：D1 estop 用例 `set Safety_OK=False` 被 plant→PLC 桥接的默认值 True 冲掉——增加 `direct_inputs` 集合，DSL 直接写入的点优先级高于桥接。
4. `Safety_OK` 未声明初始值时程序恒断电——`_one_scan` 对**每个声明输入**喂值（plant 桥接值或 ST 初始化默认），消除"unknown input"与"隐式 FALSE"两类歧义。

## 2d. W5 Agent 闭环链路（AGENT-SC，工具层 → Debugger 归因 → Orchestrator 状态机）

> W5 落地核心 8 工具（`plcagent.agent.tools`）、Debugger 归因规则 D1~D8（`plcagent.agent.debugger`）、LLM 网关（`plcagent.agent.llm`）、Orchestrator 状态机（`plcagent.agent.orchestrator`）。链路：**Spec → 工具校验 → 生成 → 静态门 → 仿真（唯一入口 sim.run）→ 失败归因 → 回 Design**。

| 场景 | 验证点 | 用例数 | 结果 |
|---|---|---|---|
| 工具门禁 | spec.validate/ir.check/gen.render/sta.check 对好/坏 Spec 的判定（V6 重复优先级拦截、生成纯函数、生成 ST 过 S 规则） | 4 | ✅ PASS |
| sim.run 权限矩阵 | designer 角色调用被拒（4.1：仿真仅 Orchestrator 触发）；orchestrator + 桥接跑 D1 套件全绿 | 2 | ✅ PASS |
| trace.summarize | 失败断言抽取 fail_scan / 时间窗（window_scans）过滤信号事件 | 2 | ✅ PASS |
| Debugger D1~D8 | D7 首扫描 / D1 信号未翻转 / D3 互锁压制 / D5 窗口边缘 / D8 确定性破坏 | 6 | ✅ PASS |
| LLM 网关 | 成功记账 / 无效 JSON 重试后成功 / 3 次失败降级 / 调用数预算熔断 / 金额预算熔断 / Schema 违例重试 | 6 | ✅ PASS |
| Orchestrator | happy path 全程（Intake→…→Export）/ 非法状态转移拒绝 / Design 轮次预算超限升人工 | 4 | ✅ PASS |

合计 **24 个 W5 测试全绿**（仓库全套 137 passed, 1 skipped）。链路要点：

- **权限矩阵硬编码**：`sim_run` 校验 `ctx.perm == "run_sim"`，任何角色（含 Prompt 中的自称）都无法绕过；Orchestrator 是唯一携带 run_sim 的调用方。
- **expect 超窗异常**不再炸穿链路：`sim_run` 将 `RunnerError` 转为失败用例，交 Debugger 归因。
- **扫描桥接钩子**（pre_scan/post_scan）：`d1_bridge` 在物理步进前后双向同步 PLC 输出与 plant 端口，替代 W4 时代的 monkeypatch 方案（测试代码减半且复用到 Agent 链路）。
- **预算熔断**（E-LLM-BUDGET）：调用数与金额双上限，超限抛 LLMError 强制转人工（16.3）。

## 2e. W6 五道闸门链路（GATE-SC，G1~G5 全自动验证管道）

> W6 落地 `plcagent.gates`（14.1 五道闸门引擎）：G1 编译闸 → G2 静态闸 → G3 仿真闸 → G4 覆盖闸 → G5 变异闸，失败即短路（append-only 判定 + verdict SHA256）。D1 样例工程作为首个全闸门通过项目。

| 闸门 | 验证点 | 结果 |
|---|---|---|
| G1 编译闸 | Spec→render→parse 0 error；坏 Spec（Seq.done 守卫）拒绝且不产出 ST | ✅ |
| G2 静态闸 | R+S 规则 E=0；V6 重复优先级拦截（错误 Spec 变体） | ✅ |
| G3 仿真闸 | D1 三用例全绿（含 estop/push/recover，故障注入与桥接） | ✅ |
| G4 覆盖闸 | 语句覆盖 100%（路径限定语句 ID）+ 每个 VAR_OUTPUT 写过 TRUE 与 FALSE 各一次 | ✅ |
| G5 变异闸 | 6 类变异（翻转比较符/取反条件×2/AND↔OR/常量翻转/删赋值）杀死率 ≥80%；弱套件（不碰输出的 noop）必须变红 | ✅ |
| 管道 | run_gates 全绿、verdict_hash 两次运行全等（确定性判定）、坏 Spec 短路只留 G1 | ✅ |

**链路拦截记录（W6，共 3 个真实缺陷）**：
1. **解释器语句覆盖 ID 冲突**：`_execute` 的 stmt_id 是语句列表局部索引，嵌套语句与 CASE 各 arm 共用同一 ID（四个 arm 的 entry 动作共用 `2.0.c.*`），覆盖率严重失真——改为路径限定 ID（`1.c0.0` 格式），覆盖语义正确。
2. **D1 Spec 缺 Fault→Idle 复位转移**：estop 后永远停在 Fault，HMI_Fault 永不复位——G4 的 io_write 维度（每个输出须 TRUE+FALSE 各一次）直接暴露该缺口，补 `Fault→Idle when Safety_OK`。
3. **D1 套件缺回 Idle 用例**：语句覆盖 54%——Push→Idle 转移（PE 下降沿）从未走到，补 `recover_and_return` 用例后 100%。这正是 5.5 "测不全说明用例缺" 的实证。

测试：`tests/test_gates.py`（12 用例）。全套 **149 passed, 1 skipped**。

## 3. 各场景详细记录

### SC-01 单电机启停保持

**Spec 要点**：`Motor` 状态机（Idle/Run），`Start_PB AND EStop_OK` 启动，`Stop_PB OR NOT EStop_OK` 停止，急停互锁强制 `Motor_Run:=0`。

**输入脚本**（scanMs=10，120 扫描）：Start 脉冲 scan 2；Stop 脉冲 scan 50；急停断开 scan 80。

**断言与结果**：

| 断言 | 期望 | 结果 |
|---|---|---|
| Motor_Run=TRUE @ scan 3 | 启动脉冲后下一扫描吸合 | ✅ |
| Motor_Run=TRUE @ scan 49 | 自锁保持 47 扫描 | ✅ |
| Motor_Run=FALSE @ scan 51 | 停止按钮释放 | ✅ |
| Motor_Run=FALSE @ scan 81 | 急停强制断开 | ✅ |
| 5 次运行 digest 全等 | 确定性 | ✅ `95e6957a…` |

### SC-02 电机正反转互锁

**Spec 要点**：`Direction` 状态机（Stopped/Forward/Reverse），`prio 0` 的 `"*"` 边统一处理停止/急停，急停互锁双断。

**发现并修复的设计问题**：
1. 两台转移同用 `prio: 1` → 语义校验 **V6 命中**（同 from 优先级重复）——正是校验器该拦的错误，Rev 改 prio 2 后通过。
2. 同按 Fwd+Rev 双键：初版 ST 会吸合正转——补 `NOT Rev_PB` / `NOT Fwd_PB` 互斥条件后，**同按双键两路都不动**（验证互锁真实生效）。

**输入脚本**：Fwd @2、Rev @40、Stop @60；EStop 恒正常。

| 断言 | 期望 | 结果 |
|---|---|---|
| Fwd_Out=TRUE @3 | 正转吸合 | ✅ |
| Rev_Out=FALSE @41 | 换向瞬间反转未误动 | ✅ |
| Fwd_Out=FALSE @61 | 停止释放 | ✅ |
| 同按双键 @9 双输出均 FALSE | 互斥拒动 | ✅ |

### SC-03 单气缸往复 + 超时报警（故障注入）

**Spec 要点**：`Cylinder` 状态机（Retracted/Extending/Fault），`ExtTimeOut=1s` 参数，急停互锁断阀。

**用例 1 正常循环**：启动 @2 → 伸出到位 50~80（500ms 行程）→ 到位断阀 → `assert_never(Alarm_Fault=TRUE)` 全程不报警。✅

**用例 2 超时故障**（`Cyl_Extended: stuck_0` 注入，传感器恒 0）：

| 断言 | 期望 | 结果 |
|---|---|---|
| Cyl_Out=TRUE @3 | 阀得电伸出 | ✅ |
| Cyl_Out=TRUE @100 | 980ms 时仍在计时未超时 | ✅ |
| Alarm_Fault=TRUE @104 | 计满 100 扫描（1s）转 Fault 报警 | ✅ |
| Cyl_Out=FALSE @104 | 超时断阀 | ✅ |

> 注：ST 子集的 FB 调用语法（`TON(IN:=…, PT:=…)` 与 `Timeout.Q` 成员访问）属后续序列模板范围，本场景以 DINT 扫描计数器表达同一超时语义（scanMs=10 × 100 扫描 = 1s），语义等价且确定性相同。

### SC-04 手自动模式 + 急停全局复位

**Spec 要点**：`LineCtl` 状态机（Idle/Run/Fault），`prio 0` 急停 `"*"` 边进 Fault，Fault→Idle 需 `Reset_PB AND EStop_OK`，手动点动走 `manualOnly` 互锁行。

**用例 1 全状态巡游**：Auto 启动 @10 → 运行 → 急停 @40 → Fault → 复位 @70 → Manual 点动 @90~110。

| HMI_Fault=TRUE @41 | 急停亮故障灯 | ✅ |
| Conv_Run=FALSE @41 | 急停断带 | ✅ |
| HMI_Fault=FALSE @71 | 复位清除故障 | ✅ |
| Conv_Run=TRUE @91 | 手动点动经互锁吸合 | ✅ |
| Conv_Run=FALSE @111 | 松开点动释放 | ✅ |

**用例 2 复位闸门**：运行中急停 → 故障期间按住 Start 无效 → 复位后（Start 仍按住）自动恢复。
